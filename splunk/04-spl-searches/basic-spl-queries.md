# Basic SPL Queries

## Objective

Practice foundational Splunk Search Processing Language (SPL) queries for filtering, searching, and analyzing Windows Event Log data.

---

## Wildcard Searches

Wildcard searches allow partial matching using the `*` character.

### Example Query

```spl
Username=Je*
```

### Purpose

Searches for usernames beginning with:

```text
Je
```

### Example Matches

- Jeanne
- Jean

---

## Boolean AND Searches

Boolean operators can be used to combine multiple search conditions.

### Example Query

```spl
eventid=4624 AND computername=computer1
```

### Purpose

Searches for successful Windows logon events associated with:

```text
computer1
```

### Notes

Windows Event ID:

```text
4624
```

represents a successful logon event.

---

## Boolean NOT Searches

The `NOT` operator excludes matching events from search results.

### Example Query

```spl
eventid=4624 NOT computername=domaincontroller
```

### Purpose

Searches for successful logon events while excluding activity generated by the domain controller.

---

## Internal Splunk Log Queries

Reviewed internal Splunk logs for forwarder communication and ingestion verification.

### Example Query

```spl
index=_internal component=TcpOutputProc
```

### Purpose

Verified Universal Forwarder communication with the Splunk receiver.

---

## Windows Event Log Queries

Reviewed searchable Windows Event Log data ingested into Splunk.

### Example Query

```spl
source="WinEventLog:*"
```

### Purpose

Searches all ingested Windows Event Logs including:
- Security logs
- System logs
- Application logs
